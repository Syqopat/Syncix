# resources

The images in this folder, and why they are the way they are.

## icon.svg — VS Code sidebar icon

Deliberately PLAIN: a single line, no comments, no XML declaration, and the file
starts directly with `<svg`.

The reason was found by trial. The icon stayed invisible twice:

1. The first version used `stroke="currentColor"`. When VS Code reduces this icon
   to one colour it does not carry stroke attributes over, and `currentColor`
   cannot be resolved because it comes from a CSS context the sidebar does not
   have. The result: an empty slot where the icon should be, with only a tooltip
   on hover.

2. The second version used fills, but the file STARTED with a long XML comment.
   It was still invisible. That is why the file has no comments at all now.

Rule: use fills (not strokes), write the colour explicitly (#C5C5C5, VS Code's
standard icon grey), and start the file with `<svg`.

The mark is the same as the logo: the upper arrow points right (to the editor),
the lower one back to Studio.

The Marketplace does not accept user-provided SVGs, so the package ships
`icon.png` instead; the SVG stays here as the source.

## logo.svg / logo.png — Marketplace and README logo

The coloured, backed version of the same mark. The PNG is generated by
`tools/gen-logo.py`; it writes the PNG directly with zlib (no Pillow needed) and
draws at 4x size, then scales down, for anti-aliasing.

The background colour is the same as the Studio panel's: the extension, the
panel and the store listing share one palette.
